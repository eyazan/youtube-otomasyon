# ImpossibleBrief hook-candidate gate: evidence (2026-10-30)

The portfolio overlay `config/viral-quality-v2.json` sets `hooks.minimumCandidates: 20`. It is used twice:
- research write gate (`scripts/ib-ct-library/build.js`): a record with fewer candidates cannot be written;
- topic score (`core/growth/topic-scoring.js`): `HookPotentialScore` loses 8 points when `meetsMinimum` is false.

Measured over the 154 researched IB records (`core/growth/hooks.js` generate, current config):

| | records |
|---|---|
| ≥ 20 candidates | 1 |
| ≥ 16 candidates | 27 |
| candidates per record | 10–21 (median 13–14) |
| distinct valid families | 5–12 (most 7–9) |
| published IB Shorts | 19 of 19 had 10–17 candidates |

The generator has 18 fixed families and merges cosmetic repeats, so 20 cannot be reached by adding real variety;
it could only be reached by padding, which the dedupe step already refuses. The count is therefore not a quality
signal: it blocks all new research (batch-11 records had 16) and costs nearly every record 8 HookPotential points.

Proposal (this PR, **off by default**): `hookCandidateGate` in `channels/impossible-brief/growth-engine.json`, applied
only with `enabled: true` and a named `approvedBy`:

| rule | value |
|---|---|
| valid (unblocked) candidates | ≥ 16 |
| distinct families among them | ≥ 7 |
| candidates scoring ≥ 70 | ≥ 8 |
| selected hook score | unchanged (≥ 76, v2) |
| viral minimum | unchanged (75) |

Under it 20 of 154 records meet the gate (16+/7+/8+ and a selected hook ≥ 76). With it enabled in a local preview the
qualified IB buffer stays **0** (best 74): the gate changes which records can be written and removes an unreachable
penalty; it opens no topic by itself. FR, CT and HLT are unaffected (the gate is channel-scoped; FR buffer 11 → 11).
Meeting the gate is never a publication approval: source ledger, visual mechanism, technical QA, Creative Director
review and the publication policy still apply.
